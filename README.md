# 哨兵 SepsisGuard · 脓毒症早期预警与远程监护平台

> 在同样的数据与评测口径下，机器学习相对临床现用的规则评分（NEWS2 / SIRS / qSOFA）究竟提升了多少？提升体现在哪里？代价是什么？

> **本系统输出的是风险提示，不构成医疗诊断，临床决策请遵医嘱。**

---

## 这是什么

脓毒症的早期表现不特异，临床目前主要依靠经验判断与若干**规则型评分系统**（SIRS / qSOFA / NEWS2）。这些评分只使用当前时刻的数值，不利用时间趋势，也不利用检验指标之间的组合信息——而 ICU 每时每刻都在产生高密度时序数据。

本项目把三件事放进**同一个可比框架**里：临床规则基线、经典机器学习、深度时序模型。三层使用**完全相同的数据划分、评测代码与指标**，确保对比公平。

其中"代价"指**误报率**——临床对预警系统最大的顾虑不是算得不够准，而是误报多到医生干脆不看。因此本项目把误报率与提前预警时间提到与精度同等位置。

## 核心结果

测试集 **3,003 位患者，其中 263 例脓毒症**。所有指标均按 PhysioNet/CinC Challenge 2019 官方效用函数严格对齐。

| 模型 / 方法 | 官方效用分数 | AUROC | AUPRC | 中位提前预警 (h) | 误报率 (次/患者日) |
|---|---:|---:|---:|---:|---:|
| **第一层 · 临床规则基线** | | | | | |
| qSOFA | −0.0084 | 0.5431 | 0.0242 | 27.5 | 0.365 |
| SIRS | +0.0673 | 0.5823 | 0.0284 | 23.0 | 0.990 |
| NEWS2 | +0.0795 | 0.5947 | 0.0300 | 27.5 | 1.252 |
| **第二层 · 经典机器学习** | | | | | |
| 逻辑回归 | +0.0204 | 0.7908 | 0.0982 | 21.5 | 0.831 |
| **LightGBM** | +0.3812 | **0.8190** | 0.1139 | **27.0** | 0.253 |
| **XGBoost** | **+0.4078** | 0.8186 | **0.1144** | 26.0 | **0.233** |
| **第三层 · 深度时序模型** | | | | | |
| Transformer | +0.2794 | 0.7681 | 0.0818 | 19.0 | 0.328 |
| LSTM | +0.7623 | 0.9824 | 0.6797 | 1.0 | 0.234 |

| 指标 | NEWS2 | XGBoost | 变化 |
|---|---:|---:|---|
| 官方效用分数 | +0.0795 | +0.4078 | **约 5.1 倍** |
| AUROC | 0.5947 | 0.8186 | **+0.2239** |
| 误报率 | 1.252 | 0.233 | **降低 81%** |

**外部验证（Set B，不同医院，20,000 位患者）**

| 指标 | 内部测试集 | 外部验证集 |
|---|---:|---:|
| AUROC | 0.8190 | **0.7965** |
| 患者级特异度 | 0.682 | **0.814** |
| 阴性预测值 NPV | 0.965 | **0.974** |
| 中位提前预警 | 27.0 h | **33.0 h** |
| 误报率 | 0.253 | **0.145** |

> **NPV 0.974 是最有临床价值的数字**：当系统判定某位患者"无需特别关注"时，
> 该患者确实未发生脓毒症的概率为 97.4%——医护可以安全地把注意力从低风险患者
> 身上移开。这正是"减少漏诊而非替代医生"这一定位的直接体现。

### 三个必须一起说的结论

1. **模型几乎不使用瞬时值**——去掉全部 34 个瞬时值特征后 AUROC 仅变化 −0.0005，而"仅保留当前时刻值"会让 AUROC 下降 0.1362。增益**主要来自时序信息**。
2. **LSTM 的高分是个陷阱**——逐小时 AUROC 0.9824 很亮眼，但它**中位只提前 1.0 小时**报警。逐小时判别力 ≠ 提前预警能力；作为早期预警系统，经典梯度提升模型性价比更高（1/3 训练时间换 27 小时提前量）。
3. **修正了一个会系统性高估性能的特征缺陷**（`never_measured` 的 train/serve skew，影响 AUROC 0.0248）。修正后"缺失模式特征贡献最大"的结论不再成立——该结论原先主要来自泄漏特征。

## 方法学

- **863 维特征**：瞬时值、4/8/12/24 小时窗口统计量、趋势斜率、缺失模式特征、临床派生指标。缺失值不做全局填充——LightGBM/XGBoost 原生处理 NaN，NaN 的走向本身携带分支信息。
- **训练 / 推理一致性**：不是靠约定，而是靠结构——两者调用同一个函数 `features._patient_feature_block()`，已用测试验证逐位相同。
- **数据划分**：严格按患者划分，并以**会抛错的断言**强制校验三个集合两两无交集、并集覆盖全部患者、各集合阳性比例合理。这是时序临床数据上最容易犯且后果最严重的错误。
- **关于数据泄露的三项独立检验**：因果性（截断历史）12h AUROC 0.9058 < 72h 0.9473；合成随机数据 AUROC 0.5921；**患者级标签重排（决定性）AUROC 0.4955，纯随机水平**。
- **可解释性**：不展示 SHAP 数值，而是转换为临床语言——不显示"shock_index 贡献 +0.18"，而显示"休克指数高于正常范围，是本次风险升高的主要原因"。此外给出信息缺口提示，把模型的不确定性转化为可执行的临床动作。

## 界面

八个页面，从"数据怎么进来"到"结论怎么交付"形成完整闭环：

| 页面 | 用途 |
|---|---|
| **控制台** | 病区态势决策句、数据脉象层、高密度患者清单、患者详情抽屉 |
| 经典看板 | 卡片视图，适合快速浏览与教学演示 |
| 数据接入 | 七条通路（文件 / HL7 v2 / REST / FHIR / 推送 / 动态仿真 / 手动录入）的配置与自检 |
| 接口文档 | 院内对接方式、端点清单、报文示例、拒绝原因对照（离线可读） |
| 动态监护 | 100 位患者的连续数据流，虚拟时间可推进 / 暂停 / 快进 / **回放**；按监护场景分区；每位患者一份病程观察日志 |
| 手动录入 | 全部 **40 项**指标滑条，滑条底色直接画出正常区 / 注意区 / 危险区；录入即出结论 |
| 报告中心 | 九节结构化评估报告（风险结论 / 告警明细 / 规则核对 / 指标逐项 / 指标趋势 / 信息缺口 / 归因 / 时间线 / 文字结论），可打印、可下载 Markdown |
| 观察日志 | 跨患者浏览、追加医护记录、导出 Markdown |

**双模式运行**：页面加载时探一次后端——能连上就用后端（真实模型产物），连不上就用页面内置的仿真内核。**直接双击打开任一页面都能完整演示**，不会出现"初始化失败""请启动后端服务"。

界面上还做了**色盲安全**处理：风险分级同时用颜色、文字标签与形状编码（极高=菱形、高=方块、中低=圆点），不单靠色相区分。

## 本仓库（`sepsisguard`）是什么

这是**评委演示用的静态快照版**，由开发者本机的完整运行结果固化而成：

- 600 位患者的风险分、告警与归因，均为真实 LightGBM / XGBoost 推理产物
- 806 条告警，含触发时间、等级、原因
- 全部 863 维特征工程与三层模型评测的原始结果

**与开发者本机原生版的关系**：界面代码、样式、交互、图表与原生版**完全相同**，仅六处极小的补丁用于如实说明"这是固化快照、没有后端进程"。逐字段核对结果：患者数、风险分级计数、决策句、数据脉象层、分级阈值、模型版本、首位患者的床号与风险分**全部一致**。

## 落地边界

- **定位边界**：输出"该患者风险升高，建议关注"级别的提示，**不给诊断结论**，不推荐具体用药。
- **责任边界**：设计目标是**减少漏诊**，不替代医生。每一级告警都对应"建议采取什么行动"的提示，而非"应当如何处置"。
- **告警疲劳防范**：界面上提供"忽略并说明原因"的操作，把无效告警转化为后续优化的依据。
- **公网演示的边界**：静态快照版不包含真实系统对接能力（文件 / HL7 / REST / FHIR / 推送）。那需要一个能读写文件、维持长连接的进程，浏览器沙箱做不到——**这是浏览器安全模型的硬限制**。一旦接入院内真实数据，不应将服务直接暴露在公网。
